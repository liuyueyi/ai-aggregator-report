### 一、推理与评测方法论

#### 3. [WorldCup Arena：无泄漏的前瞻式前沿 LLM 实时锦标赛评测](https://arxiv.org/abs/2608.04008v1)
- **来源**: arXiv（cs.CL） | **时间**: 近3天
- **摘要**: 以 2026 世界杯 39 天 104 场比赛为对象，要求在每次开球前预测 7 个盘口，共归档 4,494 条预测——作答时答案尚不存在，所以评测天然无泄漏。
- **深度洞察**:
  * 创新点 / 方法：反其道而行，用"未来未知事件"替代 retrospective filter，从结构上规避记忆泄漏。
  * 影响 / 意义：6 个前沿模型在胜负上平均 63.9%，与下注庄家热门持平；**它们彼此比正确更趋同，多数投票毫无增益**，且对平局和进球数集体低配、比分扎堆单一。真实业务中"多个模型投票"并不必然更准，是重要提醒。

#### 6. [Test-Time Scaling 在推理 LLM 中的系统化：推理机制、评测与可复现性](https://arxiv.org/abs/2608.04001v1)
- **来源**: arXiv（cs.LG） | **时间**: 近3天
- **摘要**: 把"测试时扩展"统一化为**自回归前缀树上的预算化推理**，区分三种结构机制：单轨迹顺序扩展、叶级扩展（末端归约）、前缀级扩展。
- **深度洞察**:
  * 创新点 / 方法：首次给各类 TTS 算法一个统一统计框架，并把评测对象从"模型"改为"整个推理系统"。
  * 影响 / 意义：不看推理协议只报准确率让结果无法跨研究比较，这份工作给了落地工程（预算分配、投票/验证聚合）清晰的分类学。

### 二、Agent 能力与自我改进

#### 1. [ParVL：多模态 LLM 的并行扩展与可扩展算力分配](https://arxiv.org/abs/2608.04010v1)
- **来源**: arXiv（cs.CV） | **时间**: 近3天
- **摘要**: 通过复用共享的 ViT 与 LLM 主干，在多个视觉/语言分支间并行扩展，并系统研究固定骨干预算下"算力该分给视觉还是语言"的权衡。
- **深度洞察**:
  * 创新点 / 方法：用分支专属前缀参数实例化每条并行流，端到端全参微调约 13B tokens。
  * 影响 / 意义：挑战"多头/多模态就得堆参数"的常识，给多模态推理的算力-成本平衡提供新分配方法。

#### 2. [SocietyBench：预测反事实的社会演化](https://arxiv.org/abs/2608.04009v1)
- **来源**: arXiv（cs.CL） | **时间**: 近3天
- **摘要**: 收集五大平台新闻与社媒流，蒸馏成"事实时间线 + 公众观点层"分离的基准，并做实体替换与日期平移，生成反事实社会世界来防记忆。
- **深度洞察**:
  * 创新点 / 方法：把评测重心从"能不能完成任务"转向"懂不懂社会事件如何展开"，概率校准与时间精度两条正交轴。
  * 影响 / 意义：6 个前沿模型最高仅 75/100（锚点 50），且校准强但时间弱、或反之——**社会常识仍是 Agent 的重大短板**，对安全与长周期 Agent 是关键信号。

#### 5. [PAST-Bench：评测个人 Agent 递归自我改进的基础](https://arxiv.org/abs/2608.04003v1)
- **来源**: arXiv（cs.CL） | **时间**: 近3天
- **摘要**: 隔离评测"个人 Agent 能否把跨会话保留的经验转化为更好的行为"，覆盖 26 个场景 204 个 episode，开关保留经验做对照；据此开发 Hermes+,提升平均经验增益并提供更清晰的路径证据。
- **深度洞察**:
  * 创新点 / 方法：把"经验留存→行为改进"从口号变成可测能力，且区分"效果提升"是否真的走了正确的 save/retrieve/update 通路。
  * 影响 / 意义：个人 Agent 产品的长期竞争力就在记忆与自我改进，本基准对 Agent 架构选型有直接参考价值。

#### 4. [TurnSight：工具集成推理的回合级 hindsight 自蒸馏](https://arxiv.org/abs/2608.04007v1)
- **来源**: arXiv（cs.CL） | **时间**: 近3天
- **摘要**: 用执行条件化的 hindsight 构造多种前瞻视界，再做跨视界方向一致性筛选，最后按 sibling rollout 归一化来调制 RL advantage。
- **深度洞察**:
  * 创新点 / 方法：把奖励信号细化到单回合工具调用，缓解长程 TIR 的稀疏奖励与信用分配难题。
  * 影响 / 意义：对工具调用型 Agent 的训练稳定性是方向性探索，TIR + RL 的实践者可参考。

### 三、表征与基础架构

#### 7. [Agogic：面向 LLM 原生文本到符号音乐的"演奏时序" token](https://arxiv.org/abs/2608.03999v1)
- **来源**: arXiv（cs.SD） | **时间**: 近3天
- **摘要**: 固定 Qwen3.5、数据、预算与解码，只换 token 化方案比较七种表征——结论是**表征而非模型规模才是分布保真度的决定变量**。
- **深度洞察**:
  * 创新点 / 方法：首次把"怎么 token 化音乐"从其他变量中隔离出来；新增 10ms 时序 + 逐音符 velocity 的 PMT 表征。
  * 影响 / 意义：PMT 让 0.8B 模型在 FMD 上超过 27B 逐拍网格模型（159 vs 272-286），且 26M 超小底座同样成立——**音乐生成产品的瓶颈在表征设计而非一味堆参数量**，冲击力很强。

#### 8. [当注意力失明：ALiBi 位置编码的数值失效](https://arxiv.org/abs/2608.03994v1)
- **来源**: arXiv（cs.CL） | **时间**: 近3天
- **摘要**: 指出 ALiBi 的线性偏置在浮点精度下会发生下溢，让大量注意力权重归零、头部部分失明，严重影响 token 检索；提出四种训练期缓解策略。
- **深度洞察**:
  * 创新点 / 方法：识别出此前被忽视的稳定性缺陷，并用 1.48 亿参数消融把它与上下文退化剥离开。
  * 影响 / 意义：默认 ALiBi 斜率对 needle-in-a-haystack 仍是强基线，但长上下文产品若复用 ALiBi 类结构，应自查下溢风险。对复现该结构的团队是及时警示。

#### 11. [LLM 能恢复编译器遗漏的语义优化机会吗？](https://arxiv.org/abs/2608.03983v1)
- **来源**: arXiv（cs.PL） | **时间**: 近3天
- **摘要**: 提出 SeGaBench（120 个可执行用例），让 LLM 从异构 C/C++ 上下文中恢复编译器表示里缺失的使能语义，并产出可验证、契约保持的优化产物。
- **深度洞察**:
  * 创新点 / 方法：只当"投机式语义提议者"，产物必须经正确性 + 语义验证器把关。
  * 影响 / 意义：最强模型 94.8% 响应给出正确产物、83.3% 带来 ≥1.05x 加速——把 LLM 从"写代码"推进到"做可信编译优化"，是编译器 + 性能工程的方向性探索。
